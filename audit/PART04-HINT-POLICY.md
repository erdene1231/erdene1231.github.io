# Current hint policy (v47)

The latest user instructions supersede the earlier minimalist-only counter removal and preserve-tracking requirements. No problem mode/page/picker/practice shows a hint-used/total counter. Hints themselves remain staged; Low hides hints, High requires authored hints/editorial.

Opening hints changes only current-view memory. Leaving the problem, reload or changing account resets the reveal state. Revealing, hiding and changing hint language do not write progress, localStorage, learner activity or analytics. They do not change problem status. Historical hint usage is not selected from the backend or used for filters/profile lists. The obsolete hinted-status option is removed; stale filter inputs are treated as unrestricted.

Current progress projection contains only status and notes. Existing v1 local blobs are read only to recover those fields, never overwritten/deleted; v2 stores the new projection. Existing unsynced status/notes can still sync, but legacy hint-induced pending activity is not imported. New backups are v2; v1 imports retain status/notes only. Old hint-language preferences are not consumed or overwritten. Current language selection is in memory.

Explicit status/notes updates whitelist columns and omit hints, with defaultToNull:false. Existing historical database values remain unchanged on conflict updates; new rows use the existing hints default. No schema change, deletion, cleanup, RLS/permission change, production read/write or migration was performed. The historical column/records remain; any later cleanup is a separate proposal requiring authorization.

Verification: tests/current-progress.test.mjs checks non-reading projection, backup compatibility and representative PGlite column-limited upsert preserving historical values/other users. tests/browser/hint-history.py checks actual frontend guest/account changes, no reveal Storage/upsert calls, route/reload resets, explicit notes persistence, legacy blob preservation and Low suppression. tests/browser/hint-math.py checks bundled MathJax and no reveal persistence. Mode/catalog/page/priority regressions cover all modes, responsive themes, progress and hidden tags. Synthetic RPC/Auth and representative SQL do not establish deployed PostgREST/live authentication verification.
