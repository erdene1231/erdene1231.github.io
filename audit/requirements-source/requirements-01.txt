# 2. TUTORIALS — Сургалтын агуулгыг үндсээр нь сайжруулах

Энэ бол төслийн **хамгийн өндөр ач холбогдолтой** хэсэг.

Одоогийн DSA tutorial-уудын тайлбар хангалттай гүн биш байна. Тэдгээрийг USACO Guide шиг дэлгэрэнгүй, ойлгомжтой, логик дараалалтай, жинхэнэ сурах бичгийн чанартай болго.

Tutorial бүр дараах бүтцийг баримтална.

## 2.1. Тухайн алгоритм яагаад хэрэгтэй вэ?

Tutorial-ийн эхэнд шууд алгоритмын тодорхойлолт бичиж болохгүй.

Эхлээд сурагчид тулгарч болох асуудлыг тайлбарла.

Жишээлбэл, Binary Search tutorial:

- Бидэнд эрэмбэлэгдсэн 1,000,000 элементтэй массив байна.
- Нэг элементийг олохын тулд бүгдийг нь шалгавал юу болох вэ?
- Яагаад энэ арга үр ашиг муутай вэ?
- Массив эрэмбэлэгдсэн гэдэг мэдээллийг хэрхэн ашиглаж болох вэ?
- Яаж хайлтын талбайг багасгах вэ?

Энэ мэтчилэн сурагч алгоритм сурахаасаа өмнө **тухайн алгоритмыг хэрэглэх шаардлагыг ойлгох** ёстой.

Алгоритмыг ямар бодлогод, ямар нөхцөлд хэрэглэх нь тохиромжтойг тайлбарла.

## 2.2. Гол санааг сурагч өөрөө нээж байгаа мэт тайлбарлах

Алгоритмын эцсийн хувилбарыг шууд өгч болохгүй.

Дараах дарааллаар ойлгуул:

1. Энгийн, шууд шийдэл.
2. Шууд шийдлийн сул тал.
3. Асуудлыг хялбарчлах ажиглалт.
4. Илүү үр ашигтай шийдэлд хүрэх үндсэн санаа.
5. Алгоритмыг бүрэн гарган авах.

Ингэснээр сурагч зөвхөн алгоритмыг цээжлэх биш, **ижил төстэй шинэ алгоритмыг өөрөө нээж сурах** ёстой.

## 2.3. Алгоритм хэрхэн ажилладаг вэ?

Алгоритмыг жижиг жишээгээр тайлбарла.

Шаардлагатай үед:

- Массивын төлөв
- Заагчдын байрлал
- Графын traversal
- Модны өөрчлөлт
- DP хүснэгт
- Segment tree-ийн бүтэц
- Алгоритмын алхам бүрийн төлөв

зэргийг дүрслэн үзүүл.

Боломжтой үед интерактив visualization нэм.

Гэхдээ интерактив дүрслэл нэмэхийн тулд хуудасны performance-ийг муутгаж болохгүй.

## 2.4. Яагаад зөв ажилладаг вэ?

Алгоритмын зөв байдлыг тайлбарла.

Шаардлагатай үед:

- Loop invariant
- Induction
- Exchange argument
- Contradiction
- Greedy stays ahead
- DP state болон transition-ийн зөв байдал
- Graph algorithm correctness

зэргийг ашигла.

1300–1400 түвшний сурагч ойлгохуйц энгийн тайлбараас эхэлж, дараа нь албан ёсны баталгааг гарга.

Зөв байдлын баталгааг алгасаж, зөвхөн код үзүүлдэг tutorial битгий хий.

## 2.5. Яагаад хурдан ажилладаг вэ?

Алгоритмын хугацааны нийлмэл байдлыг зөвхөн томьёогоор хэлээд орхиж болохгүй.

Жишээлбэл:

**Binary Search: O(log n)**

Яагаад?

- Нэг алхамд боломжит хариултын муж ойролцоогоор хоёр дахин багасдаг.
- n элементээс n/2, n/4, n/8 ... болж багасна.
- Ойролцоогоор log₂(n) алхмын дараа ганц боломж үлдэнэ.

Ингэж ойлгуул.

Tutorial бүрд:

- Time complexity
- Space complexity
- Хамгийн муу тохиолдол
- Шаардлагатай үед amortized complexity
- Хязгаарлалтаас боломжит алгоритм сонгох логик

зэргийг тайлбарла.

Мөн ямар нөхцөлд тухайн алгоритм хангалтгүй болохыг дурд.

## 2.6. Implementation-ийг хэсэг бүрээр нь тайлбарлах

Бүх implementation үндсэндээ C++17 байна.

Зөвхөн бүтэн код өгөөд өнгөрч болохгүй.

Дараах байдлаар тайлбарла:

**1-р хэсэг — Өгөгдлийн бүтэц болон хувьсагчид**

Ямар хувьсагч юуг илэрхийлж байгаа, яагаад хэрэгтэйг тайлбарла.

**2-р хэсэг — Initialization**

Анхны төлөвийг яагаад ингэж сонгосныг тайлбарла.

**3-р хэсэг — Гол алгоритм**

Loop, condition, transition, update бүрийн логикийг тайлбарла.

**4-р хэсэг — Зөв хариу гаргах**

Алгоритм дуусахад ямар invariant биелж байгааг тайлбарла.

**5-р хэсэг — Бүтэн implementation**

Дээрх хэсгүүдийг нэгтгэсэн цэвэр, ойлгомжтой C++17 код харуул.

Implementation хэсэг бүрийг expand/collapse хийх боломжтой байж болно.

Кодын шаардлага:

- Syntax highlighting
- Copy button
- Зөв indentation
- Ойлгомжтой variable naming
- Шаардлагатай comments
- Boundary cases
- Overflow, indexing зэрэг анхаарах зүйлс

## 2.7. Түгээмэл алдаа

Алгоритм бүрд Common Mistakes хэсэг нэм.

Тухайн алгоритмд тохирох алдаануудыг тайлбарла.

Жишээ нь Binary Search:

- Infinite loop
- Off-by-one error
- `mid` буруу тооцох
- Monotonic condition буруу тодорхойлох
- `lower_bound` болон `upper_bound`-ийг андуурах

Алдаа бүрд боломжтой бол жижиг counterexample өг.

## 2.8. Тухайн алгоритмын хувилбарууд

Энэ хэсгийг заавал хэрэгжүүл.

Алгоритм бүрийн холбогдох хувилбарууд болон өргөтгөлүүдийг харуул.

Жишээ нь Binary Search:

- Standard binary search
- Lower bound
- Upper bound
- Binary search on answer
- Binary search on real numbers
- Parallel binary search

Эдгээрийн ялгаа, хэрэглээ, шаардлагатай өмнөх мэдлэгийг товч тайлбарла.

**Хувилбар бүрийн нэр дээр дарахад тухайн tutorial руу очдог байх ёстой.**

Мөн:

- Prerequisite tutorials
- Related tutorials
- Advanced extensions
- Next recommended tutorial

гэсэн холбоосуудтай болго.

Холбоосыг текст дотор таамгаар бичих биш, тогтвортой tutorial ID дээр суурилсан relationship ашигла.

Одоогоор тухайн tutorial байхгүй бол холбоос эвдэрсэн байдалтай бүү харуул. Харин backlog-д бүртгэж, шаардлагатай tutorial-ийг бүтээ.

## 2.9. Ажиглалт болон problem-solving thinking

Tutorial бүрд **"Ажиглалт ба бодлого бодох арга"** хэсэг нэм.

Энэ хэсэгт:

- Бодлогын өгүүлбэрээс ямар мэдээлэл чухал вэ?
- Ямар constraint алгоритмыг санал болгож байна вэ?
- Ямар invariant ажиглагдаж байна вэ?
- Шууд шийдлийг хэрхэн сайжруулах вэ?
- Энэ алгоритмыг хэрэглэх эсэхийг хэрхэн таних вэ?
- Ямар үед энэ алгоритм буруу сонголт болох вэ?

гэдгийг бодлогын жишээтэй тайлбарла.

Энэ хэсэг Erdene Club-ийн гол ялгарах онцлог байх ёстой.

## 2.10. Тухайн сэдвийн бодлогууд

Tutorial бүрийн төгсгөлд:

**"Энэ сэдвийг эзэмших бодлогууд"**

гэсэн хэсэг оруул.

Бодлогуудыг дараах шатлалаар ангил:

- Warm-up
- Standard
- Observation
- Application
- Challenge
- Olympiad extension

Тохирох тооны, чанартай бодлого сонго. Ихэнх tutorial-д 5–12 бодлого байж болно, гэхдээ сэдвээс хамааран өөрчил.

**Priority бодлогуудыг ⭐ тэмдэглэгээтэй, бусдаас тодорхой ялгаруулж харуул.**

Priority гэдэг нь зүгээр хамгийн хүнд бодлого гэсэн үг биш.

Тухайн сэдвийг эзэмшихэд хамгийн өндөр өгөөжтэй бодлого байх ёстой.

Priority сонгох шалгуур:

- Гол алгоритмыг оновчтой ашиглуулдаг
- Чухал ажиглалт шаарддаг
- Түгээмэл алдааг ойлгуулдаг
- Шинэ төрлийн хэрэглээг үзүүлдэг
- Дараагийн түвшинд суурь болдог
- Сурагчийн бодох чадварыг хөгжүүлдэг

Priority бодлого бүрийн хувьд редакторт харагдах богино үндэслэл хадгал.

Сурагчид бодлогын шийдлийг spoiler болгож харуулахгүй.

Бодлогын жагсаалтад:

- Нэр
- Source
- Rating эсвэл estimated difficulty
- Difficulty category
- Priority
- Solved/attempted/unsolved
- Холбогдох tutorial
- Хэрэв байгаа бол 100-day plan-ийн өдөр
- Бодлого руу орох линк

харагдана.

## 2.11. Шаталсан hint

Байгаа 3-level hint системийг хадгал.

Шаардлагатай бол сайжруул.

- Hint 1: Гол ажиглалтад чиглүүлнэ.
- Hint 2: Алгоритмын санаанд ойртуулна.
- Hint 3: Шийдлийг хэрэгжүүлэх чухал алхмыг ойлгуулна.

Hint нээхээс өмнө сурагчид өөрөө бодох боломж үлдээ.

Бүтэн шийдэл болон editorial-ийг hints-тэй андуурч болохгүй.

## 2.12. Tutorial төгсгөлийн checklist

Tutorial бүрийн эцэст сурагч өөрийгөө шалгах боломжтой болго.

Жишээ нь:

# 10. SUPABASE DATABASE БА SQL MIGRATION

Энэ хэсгийг онцгой анхаар.

Өмнө нь том SQL command болон урт migration ажиллуулахад удирдах, шалгах, алдаа засахад хүндрэлтэй байсан.

Тиймээс **Supabase SQL-ийг жижиг, ойлгомжтой, тус тусдаа ажиллуулж болох хэсгүүдэд хуваа.**

## 10.1. Migration-ийн хэмжээ

Боломжтой бол:

- Нэг migration = нэг тодорхой зорилго
- Нэг migration нь богино, уншихад амар
- Том schema update-ийг олон дараалсан migration болгон хуваах

Жишээ:

- 001 — Tutorial relationships
- 002 — Tutorial prerequisites
- 003 — Tutorial progress
- 004 — Study plan structure
- 005 — Study plan progress
- 006 — Profile statistics support
- 007 — Necessary indexes
- 008 — RLS policies

Энэ бол зөвхөн жишээ. Бодит schema-г эхлээд шалга.

## 10.2. SQL ажиллуулах зарчим

Migration бүрийн хувьд:

1. Юу өөрчлөхийг тайлбарла.
2. SQL-ийг тусдаа файлд хадгал.
3. Dependencies-г тодорхойл.
4. Боломжтой бол transaction ашигла.
5. Migration-ийг давхар ажиллуулах эрсдэлийг тооц.
6. Өмнөх өгөгдөлд нөлөөлөх эсэхийг шалга.
7. Амжилттай хэрэгжсэн эсэхийг verify хийх query өг.
8. Шаардлагатай rollback эсвэл recovery арга бэлд.

**Бүх database өөрчлөлтийг нэг аварга SQL файл болгож болохгүй.**

## 10.3. Data import

Сэдэв, бодлого, 100-day plan зэрэг олон зуун өгөгдлийг урт `INSERT` statement болгон SQL Editor руу оруулах шаардлагагүй.

Үүний оронд:

- Жижиг batch
- Version-controlled JSON/CSV
- Safe import scripts
- Idempotent upsert
- Duplicate prevention

ашигла.

Боломжтой бол batch хэмжээ тохируулдаг байх.

Migration болон content import-ийг тусад нь удирд.

## 10.4. Аюулгүй байдал

- Existing RLS-г эвдэхгүй.
- User progress-д user ownership хадгал.
- Admin permissions зөв ажиллана.
- Frontend-д service-role key байрлуулахгүй.
- SQL policy-уудыг бодит account permission-тай шалга.
- Өгөгдөл устгах migration хийхээс зайлсхий.
- Production database-д нөлөөлөхөөс өмнө backup/recovery боломжийг шалга.

# 15. АЖЛЫН ТАЙЛАН БА ХАРИЛЦАА

Чи өмнө нь энэ сайтыг хөгжүүлж байсан тул шаардлагагүйгээр надаас repository-ийн үндсэн бүтэц, Supabase ашигладаг эсэх, GitHub Pages тохиргоо гэх мэт өмнө нь мэддэг зүйлсээ дахин асуух хэрэггүй.

Гэхдээ бодит төлөв өмнөх контекстоос өөрчлөгдсөн байж болох тул хэрэгтэй хэсгийг шалгаж баталгаажуул.

Үе шат бүрийн дараа монголоор:

1. Ямар ажил хийсэн
2. Ямар файл өөрчлөгдсөн
3. Ямар database өөрчлөлт орсон
4. Ямар migration ажилласан
5. Ямар контент бодитоор нэмэгдсэн
6. Ямар test амжилттай болсон
7. Ямар зүйл дутуу үлдсэн
8. Дараагийн алхам

гэсэн товч тайлан өг.

Зөвхөн төлөвлөгөө бичээд зогсохгүй, хэрэгжүүлэх боломжтой ажлуудыг бодитоор хий.

Нэг дор хэт том SQL эсвэл frontend patch хийхээс зайлсхий.

Хэрэв Supabase дээр миний гараар ажиллуулах шаардлагатай SQL байвал:

- Богино хэсэг болгон хуваа.
- Зөв дарааллаар өг.
- Яг юу хийж байгааг тайлбарла.
- Нэг хэсэг бүтэлгүйтвэл засварлахад амар байлга.

Хэрэв Work mode шууд эрхтэй, аюулгүйгээр хэрэгжүүлж болох өөрчлөлт байвал өөрөө гүйцэтгэ.

Production data-г алдагдуулах, permission сулруулах эсвэл буцаах боломжгүй үйлдэлд болгоомжтой ханд.

# 16. ЭЦСИЙН ЗОРИЛГО

Erdene Club-д орсон сурагч:

1. Profile-доо нэвтэрнэ.
2. Өөрийн progress-ийг харна.
3. 100 хоногийн төлөвлөгөөг эхлүүлнэ.
4. Өнөөдрийн сурах сэдвээ харна.
5. Тухайн алгоритм яагаад хэрэгтэйг ойлгоно.
6. Алгоритмын гол санааг алхам алхмаар сурна.
7. Яагаад зөв, яагаад хурдан ажилладгийг ойлгоно.
8. C++ implementation-ийг бие даан бичиж сурна.
9. Холбоотой алгоритмууд руу шилжинэ.
10. Тухайн сэдвийн хамгийн хэрэгтэй Priority бодлогуудыг бодно.
11. Шаардлагатай бол шаталсан hint ашиглана.
12. Өөрийн хийсэн ажиглалт, алдааг тэмдэглэнэ.
13. Өдөр тутмын progress-ийг хадгална.
14. Activity heatmap, rating distribution, tag statistics-аа харна.
15. Дараагийн түвшинд системтэй шилжинэ.

Ингэснээр Erdene Club дараах системүүдийн сайн талуудыг хослуулах ёстой:

**USACO Guide-ийн сургалтын чанар + CSES-ийн бодлогын зохион байгуулалт + Codeforces-ийн статистик + IOI-ийн problem-solving аргачлал + Erdene Club-ийн хувийн сургалтын төлөвлөгөө.**

Гэхдээ бэлэн сайтын дизайныг шууд хуулбарлахгүй. Erdene Club-ийн өөрийн танигдах өнгө төрхийг хадгал.

## ЭХЛЭХ ЗААВАР

Өмнөх төслийн контекстээ ашиглан одоогийн код болон өгөгдлийг шалга.

Хамгийн эхэнд tutorial engine болон өгөгдлийн холбоосуудыг сайжруул.

Дараа нь жишиг болгон **Binary Search, Greedy, Dynamic Programming** гэсэн гурван tutorial-ийг дээрх шаардлагын дагуу үнэхээр чанартай шинэчил.

Эдгээрийн бүтэц, problem relationships, implementation explanation, priority practice problems зөв ажиллаж байгааг баталгаажуул.

Үүний дараа үлдсэн tutorial-ууд болон problem bank-ийг системтэй өргөтгө.

Хэрэгжүүлэх явцад 100-day plan, profile, problems page, light theme зэрэг бусад шаардлагыг орхигдуулахгүй.

**Чиний зорилго бол зүгээр олон feature нэмэх биш, сурагчдын мэдээлэлзүйн олимпиадын бэлтгэлд бодит үр дүн өгдөг, чанартай сургалтын платформ бүтээх юм.**
